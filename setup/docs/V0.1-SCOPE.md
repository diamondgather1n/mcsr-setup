# v0.1 Scope

## Minimum Starting State

v0.1 supports a booted basic Arch Linux installation with working DNS and internet access, `bash`, `pacman`, and an existing `nathan` account whose home is `/home/nathan`.

The installer may run as `nathan` with working `sudo`, or as root. It does not create users, edit sudoers, enable passwordless sudo, partition disks, configure a bootloader, or configure networking. A normal user without `sudo` is told to rerun the installer as root. Root mode still requires the existing `nathan` account because user creation is outside v0.1. AUR builds always run unprivileged as `nathan`; when a root-started run reaches the AUR transaction, the helper still uses Nathan's normal sudo policy for package installation.

Git, curl, sudo, and an AUR helper are detected rather than assumed. The official package stage installs Git, curl, and sudo. The AUR stage uses `yay` or `paru` if one is available. Automatic AUR-helper bootstrap is deliberately deferred; if neither helper exists, the installer stops after the successful official package transaction and can be rerun after a helper is installed.

## Implemented

- Arch and target-user preflight checks.
- Curated official, AUR, optional, and legacy package manifests.
- A full `pacman -Syu --needed` official-package transaction.
- AUR installation through an existing `yay` or `paru` helper.
- Explicit current, legacy, and system configuration restore mappings.
- Root-owned `/etc/keyd` restoration.
- Source and destination validation with syntax checks where tools support them.
- A read-only dry run.

## Deferred

- User creation and sudoers policy.
- Automatic AUR-helper bootstrap.
- Service enablement and graphical-session startup.
- Bootloader, partition, kernel-policy, and network provisioning.
- Minecraft accounts, Prism instances, mods, SeedQueue, and Ninjabrain Bot binaries.
- OBS scenes, credentials, plugins, portal permissions, and capture workarounds.
- The unmanaged `jay.real` binary and custom GBM portal shim currently present on the reference machine.
- Browser, Discord, Spotify, Minecraft, Twitch, and other account logins.
- A complete reinstall acceptance test in a clean machine or VM.

Legacy i3/X11 configuration is restored as inactive reference material. Legacy X11 packages are only installed when `--include-legacy-packages` is explicitly supplied.
